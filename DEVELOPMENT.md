## Development Setup

```bash
# Clone repository
git clone https://github.com/Wintersta7e/Doc-Summarizer.git
cd DocSummarizer

# Create virtual environment
python -m venv venv
source venv/bin/activate  # Linux/macOS
# or: venv\Scripts\activate  # Windows

# Install the package (and dev tools) in editable mode.
# `gui` (PySide6) is needed to launch the desktop app and to type-check and
# test the ui package — without it the UI tests are skipped. Add `runtime`
# for the heavy llama-cpp-python backend when working end to end.
pip install -e ".[dev,gui]"

# Quick smoke tests
python -c "from docsummarizer.document_parser import extract_text; print('Parser OK')"
python -c "from docsummarizer.model_manager import is_model_downloaded; print('Model manager OK')"

# Quality gate (matches CI)
ruff check .
ruff format --check .
mypy
pytest --cov=docsummarizer
```

Pre-commit hooks mirroring CI are available:

```bash
pip install pre-commit && pre-commit install
```

### Reproducible installs (lockfile)

`pyproject.toml` declares loose dependency constraints (e.g.
`pypdf>=6.14,<7`). `requirements.lock` pins every transitive dependency
to an exact version + hash, generated by `uv pip compile`.

For day-to-day development, `pip install -e ".[dev]"` is fine — it
follows the loose constraints. For reproducible release builds, install
from the lockfile first:

```bash
pip install -r requirements.lock          # exact pinned versions, hash-verified
pip install --no-deps -e .                # register the local package
```

To regenerate the lockfile after editing `pyproject.toml`:

```bash
uv pip compile pyproject.toml --generate-hashes -o requirements.lock
```

(Dependabot will refresh the lockfile automatically when it opens
update PRs.)

## Module Documentation

### document_parser.py

Handles text extraction from various document formats.

**Functions:**
- `extract_text(file_path) -> tuple[str, str | None]` - Main extraction function
- `extract_from_pdf(file_path) -> str` - PDF extraction using pypdf
- `extract_from_docx(file_path) -> str` - Word document extraction
- `extract_from_rtf(file_path) -> str` - RTF extraction
- `extract_from_txt(file_path) -> str` - Plain text with encoding detection
- `get_document_info(file_path) -> DocumentInfo` - File metadata (TypedDict)

**Supported formats:**
- `.pdf` - PDF documents (via pypdf)
- `.docx` - Microsoft Word (modern XML format only; legacy `.doc` OLE files are not supported)
- `.rtf` - Rich Text Format
- `.txt`, `.md` - Plain text (with chardet-based encoding detection)

### model_manager.py

Handles LLM model downloading and inference.

**Classes:**
- `ModelConfig` - Frozen dataclass describing a GGUF model on HuggingFace
- `Summarizer` - Main summarization class

**Functions:**
- `get_models_directory() -> Path` - Get model storage location
- `is_model_downloaded() -> bool` - Check if model exists
- `get_model_path() -> Path` - Get full model path
- `download_model(progress_callback) -> tuple[Path, str | None]` - Download from HuggingFace

**Summarizer Methods:**
- `__init__(model_path, n_ctx=8192, n_threads=None, n_gpu_layers=0)` - Load model.
  `n_gpu_layers=0` keeps inference on the CPU; `-1` offloads all layers to the GPU.
- `summarize(text, summary_type, max_tokens, should_cancel, language) -> str` - Generate
  a prose summary (the CLI path). Documents longer than the context budget are
  summarized with map-reduce chunking rather than truncated; the budget is measured
  with the model's own tokenizer, since characters per token differ widely by script.
  Generation goes through `create_chat_completion`, so the model's own chat template is
  applied automatically. `language` is `"auto"` (match the document) or a language name.
- `summarize_structured(...) -> StructuredSummary` - Discrete points, each grounded in a
  quote located in the source (the GUI path, which powers trace-to-source). Falls back
  to the prose summary if the model's JSON can't be parsed.

### settings.py

Persisted user settings (`Settings` dataclass) stored as JSON under the app-data
`config/` dir: CPU thread count, GPU toggle, appearance and output language. Load/save
are tolerant of a missing or corrupt file (they fall back to defaults).

### ui/

PySide6 + QML desktop interface ("Abstract Console").

- `ui/app.py` - Entry point: builds the `QQmlApplicationEngine`, exposes the bridge to
  QML, installs an excepthook that logs uncaught errors
- `ui/bridge.py` - `ConsoleBridge`, the QML controller: document and summary state,
  settings, and a thread pool that runs model work off the UI thread
- `ui/qml/App/` - Screens (Summary, Extract, Batch, Config), the first-run overlay and
  the `Theme` singleton; bundled fonts live in `fonts/`

Screens can be rendered headless for review with `scripts/render_qml.py`.

### cli.py

Command-line interface for terminal usage.

**Usage:**
```bash
docsummarizer-cli <input> [-t TYPE] [-o OUTPUT] [-l LANG] [--gpu|--no-gpu] [--threads N] [--download-only]
```

Flags override the saved settings for that run.

## GPU Acceleration (Optional)

Inference runs on the CPU by default. To use a GPU, install a GPU-capable build of
`llama-cpp-python`, then turn it on in **Config → GPU Offload** (or pass `--gpu`
on the CLI). The app offloads all layers (`n_gpu_layers=-1`); a CPU-only build ignores
the flag, and the Config screen says so rather than offering a toggle that does nothing.

### NVIDIA GPU (CUDA)

The easiest route is a prebuilt CUDA wheel — no local CUDA toolkit required:

```bash
pip uninstall llama-cpp-python -y
pip install llama-cpp-python \
  --extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cu124
```

Pick the `cuXXX` index that suits you; a wheel built for an older CUDA runtime still
runs on a newer driver. To build from source instead (needs the CUDA toolkit and a
C++ compiler):

```bash
CMAKE_ARGS="-DGGML_CUDA=on" pip install llama-cpp-python --no-cache-dir
```

Verify:
```bash
python -c "from llama_cpp import Llama; print('llama-cpp ready')"
```

### AMD GPU (ROCm)

```bash
CMAKE_ARGS="-DGGML_HIPBLAS=on" pip install llama-cpp-python --no-cache-dir
```

### Apple Silicon (Metal)

Metal support is usually automatic on macOS with Apple Silicon:

```bash
CMAKE_ARGS="-DGGML_METAL=on" pip install llama-cpp-python --no-cache-dir
```

### Performance Comparison

| Hardware | ~Processing Time | Notes |
|----------|------------------|-------|
| CPU (8 cores) | 30-90 sec | Default, works everywhere |
| NVIDIA RTX 3060 | 3-8 sec | Requires CUDA build |

## Building Standalone Executable

### Prerequisites

```bash
pip install -e ".[gui,runtime]" pyinstaller
```

Both extras are required. Without `gui`, PyInstaller still exits successfully but
bundles no Qt, and the binary dies on start with
`ModuleNotFoundError: No module named 'PySide6'`.

### Build Commands

```bash
pyinstaller DocSummarizer.spec
```

The executable will be in `dist/DocSummarizer` (or `dist/DocSummarizer.exe` on Windows).

### Build Size

- Executable: ~200 MB (Windows) / ~240 MB (Linux). A much smaller file means an extra
  was missing from the build environment.
- Model (separate download): ~2.5 GB

**Note:** The model is NOT bundled in the executable. Users download it on first run.

## Adding New Document Formats

To add support for a new format:

1. Add an extraction function in `document_parser.py`:
```python
def extract_from_newformat(file_path: str) -> str:
    # Your extraction logic
    return extracted_text
```

2. Register it in the `_EXTRACTORS` dictionary (this is the single source of truth;
   `SUPPORTED_EXTENSION_SET` and the dialog filters derive from it):
```python
_EXTRACTORS = {
    ".pdf": extract_from_pdf,
    ".newformat": extract_from_newformat,  # Add here
    # ...
}
```

## Adding New Models

To switch to a different LLM, update `DEFAULT_MODEL` in `model_manager.py`:

```python
DEFAULT_MODEL = ModelConfig(
    repo_id="organization/model-name-GGUF",
    filename="model-name.Q4_K_M.gguf",
    name="Model Display Name",
    size_gb=4.0,
)
```

Use any instruct/chat GGUF — the model's chat template is applied automatically via
`create_chat_completion`, so you don't need to hand-edit prompts for a new format.

## Customizing Prompts

The per-type instructions live in `model_manager.py` as `_SUMMARY_INSTRUCTIONS`, and the
shared system prompt is `_SYSTEM_PROMPT`:

```python
_SUMMARY_INSTRUCTIONS = {
    "brief": "Summarize the document below in one concise paragraph...",
    "detailed": "Provide a detailed summary of the document below...",
    "structured": "Analyze the document below and provide a structured summary...",
}
```

## Thread & GPU Control

```python
# Use half of available cores (the default when n_threads=None)
summarizer = Summarizer(model_path, n_threads=os.cpu_count() // 2)

# Pin a specific thread count and offload to the GPU
summarizer = Summarizer(model_path, n_threads=4, n_gpu_layers=-1)
```

## Known Limitations

- Scanned PDFs (image-only) are not supported - text extraction required
- Password-protected files not supported
- Complex tables may not extract cleanly
